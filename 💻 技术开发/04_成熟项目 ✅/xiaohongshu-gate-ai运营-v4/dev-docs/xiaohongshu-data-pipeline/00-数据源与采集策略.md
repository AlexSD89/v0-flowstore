# 小红书数据源与采集策略

> 本文件聚焦「要采哪些数据、为什么采、多久采一次」，暂不关心具体工具实现细节（见 `01-Agent与工具架构设计.md`）。

## 1. 数据源总览

### 1.1 小红书平台内数据

- **话题 / 关键词搜索结果**
  - 说明：
    - 以关键词（如「AI工具推荐」「效率提升」「企业数字化」）或话题（`#AI工具推荐`）为入口；
    - 采集指定窗口内的热门笔记（按点赞/收藏/评论排序）。
  - 用途：
    - 发现高频内容结构与标题/封面范式；
    - 识别热门标签组合与发布时间段；
    - 为 trending 学习与 Pattern Library 提供样本。
  - 刷新频率：
    - 核心话题：每日；
    - 长尾/小众话题：每周。

- **目标账号主页数据**
  - 说明：
    - LaunchX 自有账号与标杆账号（竞品/头部 KOL）；
    - 采集近 N 条内容的标题、封面、标签、发布时间、表现数据。
  - 用途：
    - 评估自身内容与标杆差距；
    - 为「权威建设」与「账号定位」提供数据支持。
  - 刷新频率：
    - 自有账号：每日/每次发布后；
    - 标杆账号：每 2–3 天。

- **评论区与互动数据**
  - 说明：
    - 针对自有内容与重点监控内容的评论、点赞、收藏、转发；
    - 包括评论文本与简单的情感/意图标签（正向/负向/需求）。
  - 用途：
    - 舆情监控与用户需求挖掘；
    - 为「互动策略」「内容优化」「FAQ 分类」等提供依据。
  - 刷新频率：
    - 发布后 T+1h / T+24h / T+7d 进行三次重点采集；
    - 可通过定时轮询或通知触发。

### 1.2 平台外辅助数据

- **微博 / 其他社交平台舆情**
  - 说明：
    - 参考 `🧰 tools/weibo-public-opinion-analysis-system` 的架构；
    - 对「AI 工具」「企业数字化」「小红书营销」等主题进行舆情分析。
  - 用途：
    - 为小红书选题提供跨平台视角；
    - 识别跨平台热点与潜在风险话题。

- **行业资讯与报告**
  - 说明：
    - 通过 Rube/MCP 搜索行业报告、新闻、研究文章；
    - 目前仅在文档层记录，具体自动化交由 Claude 执行。
  - 用途：
    - 为「中长线选题」「方法论升级」提供背景素材。

## 2. 采集策略原则

1. **运营驱动优先**：
   - 只采对「选题」「标签优化」「内容结构优化」「实验设计」有直接价值的数据；
   - 不做无目标的全量爬取，避免数据噪音与合规风险。

2. **渐进增强**：
   - Phase 1 以 LaunchX 客户的核心话题/账号为试点；
   - 验证数据管道稳定与可解释后，再扩展到更多行业/Client。

3. **工具复用优先**：
   - 优先复用 `xiaohongshu-mcp`、`weibo-public-opinion-analysis-system` 等已有工具工程；
   - Codex 只在本地文档中描述工具角色与数据 schema，不直接重写采集代码。

4. **结果可回放**：
   - 所有采集数据必须带有时间戳、来源、采集策略（关键词/话题/账号等）；
   - 为后续在 Evolution 层重放「当时的趋势/舆情」提供条件。

## 3. LaunchX 客户阶段性重点

> 以 LaunchX AI 评测平台为首个 Client，后续其他行业 Client 可复用同一结构，替换关键词与账号集合即可。

- 关键词/话题初始集合：
  - `AI工具推荐`、`效率提升`、`办公神器`、`企业数字化`、`AI选型` 等；
- 目标账号集合：
  - LaunchX 自有账号；
  - 行业内头部评测号、知名机构媒体号（待在 Strategy 文档中维护名单）。
- 舆情重点：
  - 对 LaunchX 品牌与核心评测内容的情感分布与高频问题；
  - 负向情绪预警（如「割韭菜」「广告」等敏感反馈）。

后续在 `01-Agent与工具架构设计.md` 中，会把上述数据源与具体 Agent/工具一一关联。
