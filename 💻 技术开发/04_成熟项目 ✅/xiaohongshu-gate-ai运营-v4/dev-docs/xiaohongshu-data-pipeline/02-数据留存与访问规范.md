# 小红书数据留存与访问规范

> 本文件规定：数据在仓内/外部系统如何存放、命名和访问，以支持后续 Spec、演化系统和工具复用。

## 1. 目录结构与命名约定（Client 视角）

以 V1 的 `clients/launch-x` 为例，抽象出标准 Client 数据目录结构：

```text
clients/<slug>/
  data/
    intel/          # 情报输入（Rube/MCP/外部搜索结果）
    drafts/         # 内容草稿（尚未发布的文案、脚本）
    learning/       # 学习结果（trending 学习、评论情感等）
    quality_logs/   # 质量日志（自动/人工评估结果）
    performance/    # 内容表现数据（曝光/互动/转化等，可按需扩展）
  assets/
    content/        # 已审核/定稿的内容
    generated/      # AI 生成的图片/视频/附件
  logs/             # 运行日志（可按时间/任务分文件）
  reports/          # 报告（周报、Auto Iteration 报告等）
```

约定：

- `<slug>` 为 Client 唯一标识，如 `launch-x`、`auto-eval` 等；
- 所有自动化任务在写入数据时，都应遵循上述目录结构；
- 自定义子目录应尽量挂在上述一级目录下，避免散落在项目根目录。

## 2. 文件命名约定

推荐格式：

```text
<name>_<YYYY-MM-DD>[T<HHMMSS>Z].<ext>
```

- `<name>`：描述性名称，使用英文/拼音，避免空格；
- 日期部分：表示采集/生成日期；
- 可选时间部分：表示具体时间点或批次号；
- 扩展名：根据内容类型选择 `.json` / `.md` / `.csv` / `.parquet` 等。

示例：

- 情报数据：`sense_round_2025-10-11.json`
- trending 学习结果：`trending_learning_20251009_212454.json`
- 质量日志：`quality_log_2025-10-11.json`
- Auto Iteration 报告：`Auto_Iteration_Report_20251009T132454Z.md`

## 3. 与 Spec / SDK 的字段映射

为实现「Spec ↔ 数据」互相引用，需要约定好字段与路径映射：

### 3.1 Post Spec 中的 `trending_snapshot_id`

- 含义：指向一次 trending 学习结果，用于说明本篇内容的趋势依据；
- 对应数据路径：
  - `clients/<slug>/data/learning/trending_learning_*.json`
- 使用方式：
  - 在填写 Post Spec 时，选择最新或特定日期的 trending 文件，并将文件名或 ID 填入该字段；
  - Claude 在生成内容/计划时，可根据该 ID 加载对应的 JSON 做进一步分析。

### 3.2 Experiment Log 与性能数据

- 实验日志（未来规划）：
  - 建议存放在 Evolution 层（如 `dev-docs/xiaohongshu-ops-spec/experiment-log-2025Q4.md`），
    其中记录的 performance 数据引用 `clients/<slug>/data/performance/*.json`。
- Auto Iteration 报告：
  - 由 `update_spec_from_feedback.py` 生成，存放在 `clients/<slug>/reports/` 下；
  - Evolution 层可根据报告中的引用，跳转到具体的数据文件。

## 4. Codex / Claude 对数据的访问模式

### 4.1 Codex（本地文档与代码修改）

- 只读/写：
  - 文档中的路径与 schema 说明；
  - 样例 JSON/Markdown 文件（小数据量），用于演示。
- 不做：
  - 大规模数据采集；
  - 实际调用小红书/微博等线上平台。

### 4.2 Claude / Gate OS（实际运行）

- 负责：
  - 按本规范在对应目录下写入/更新数据文件；
  - 在每次执行后，把「输入/输出路径」记录在 Summary 或日志中；
  - 在 Evolution / Pattern Library 设计中，引用这些路径进行分析。

---

## 5. 与 Evolution 层的关系（预告）

- Evolution 层文档（`dev-docs/xiaohongshu-evolution-system/`）将基于本规范：
  - 定义 Experiment Log 的记录格式与字段；
  - 定义 Pattern Library 的性能指标来源（哪些 performance 数据字段）；
  - 定义季度认知快照（Qx-knowledge-snapshot）要引用的数据集合。

- 本文件是「数据如何存」的约定，Evolution 层是「如何用这些数据升级范式和方法论」的约定，两者配合实现完整的学习闭环。
