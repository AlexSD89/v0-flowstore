# Gate OS 内核 · 模块与接口设计

> 本文件详细展开 `00-总体架构.md` 中的四大职责域，
> 用“模块 → 主要职责 → 建议接口 → 预期代码位置”的方式做成一页式设计参考。

## 1. AgentRuntime 模块

### 1.1 设计目标

- 为所有 Agent 提供统一的运行时环境：
  - 生命周期：start/stop/restart；
  - 健康检查：healthcheck；
  - 日志与度量：log / metrics。
- 负责 Agent 与底层 CC 的资源协调：并发 / 连接池 / 超时策略。

### 1.2 建议接口（概念级）

```python
class AgentRuntime:
    """Gate OS Agent 运行时抽象接口（设计层，用于约束实现）"""

    async def start_agent(self, agent_id: str, config: dict) -> str:
        """启动指定 Agent，返回运行实例 ID。"""

    async def stop_agent(self, instance_id: str) -> None:
        """停止 Agent 实例。"""

    async def get_status(self, instance_id: str) -> dict:
        """查询 Agent 实例状态（运行中/失败/完成等）。"""

    async def dispatch_task(self, instance_id: str, payload: dict) -> dict:
        """向 Agent 实例派发任务，返回任务结果或任务 ID。"""
```

### 1.3 预期代码位置

- 未来建议在 `src/gate_os/agent_runtime.py` 中实现；
- 现有相关逻辑可在演进中逐步迁移或对齐。

## 2. SkillsEngine 模块

### 2.1 设计目标

- 统一管理 Skills 的注册、发现与调用；
- 为 Project/Client SDK 提供稳定的 Skill 调用接口，而不直接暴露底层 CC 实现细节；
- 支持：
  - 通用 Skills（如“搜索/总结/翻译/代码分析”等）；
  - 领域特定 Skills（如“小红书内容重写”、“标签推荐”）。

### 2.2 建议接口（概念级）

```python
class SkillsEngine:
    """Gate OS Skills 引擎抽象接口"""

    def register_skill(self, name: str, descriptor: dict) -> None:
        """注册一个 Skill，descriptor 可包含类型、能力范围、底层实现引用等。"""

    def list_skills(self, filters: dict | None = None) -> list[dict]:
        """列出可用 Skills，支持按领域/能力过滤。"""

    async def invoke(self, name: str, payload: dict, context: dict | None = None) -> dict:
        """调用指定 Skill，由 Gate OS 负责桥接到底层 CC / MCP / 外部服务。"""
```

### 2.3 预期代码位置

- 建议：`src/gate_os/skills_engine.py`

## 3. EvidenceLedger & LOAManager 模块

### 3.1 设计目标

- EvidenceLedger：
  - 统一记录决策过程中用到的证据：来源、类型（实验/日志/面板数据等）、置信度；
  - 支持“三角校验”和置信度计算；
  - 可追溯：给定一个决策 ID，可以还原证据链。

- LOAManager（自主等级管理）：
  - 根据任务类型、风险、证据质量，确定 LOA 等级（0–4）；
  - 在执行前给出“是否自动执行 / 是否需要人类确认”的决策建议。

### 3.2 建议接口（概念级）

```python
class EvidenceLedger:
    """证据账本抽象接口"""

    async def record(self, claim_id: str, evidence: dict) -> str:
        """记录一条证据，返回 evidence_id。"""

    async def triangulate(self, claim_id: str) -> dict:
        """对某个 claim 做三角校验，返回综合评估结果。"""

    async def confidence(self, claim_id: str) -> float:
        """计算某个 claim 的置信度分数。"""


class LOAManager:
    """自主等级管理抽象接口"""

    async def analyze_task(self, task: dict) -> dict:
        """分析任务特征（复杂度、风险、影响范围等）。"""

    async def determine_level(self, analysis: dict, evidence_confidence: float) -> str:
        """结合任务分析和证据置信度，返回 LOA 等级（LOA0-LOA4）。"""
```

### 3.3 预期代码位置

- `src/gate_os/evidence_ledger.py`
- `src/gate_os/autonomy_manager.py`

## 4. WorkflowOrchestrator 模块

### 4.1 设计目标

- 接收 Project/Client SDK 发来的 Intent Package；
- 按照 5 步认知流程调用 CC 能力：Collect → Model → Compare → Align → Deliver；
- 协调 AgentRuntime / SkillsEngine / Evidence & LOA 的调用顺序；
- 统一负责结果回写（到 Spec、日志、实验记录等）。

### 4.2 建议接口（概念级）

```python
class WorkflowOrchestrator:
    """Gate OS 工作流编排抽象接口"""

    async def handle_intent(self, intent: dict) -> dict:
        """处理来自 SDK 的意向包，返回执行结果摘要。"""

    async def collect_phase(self, intent: dict) -> dict:
        """Collect 阶段：外部搜索、本地资产收集。"""

    async def model_phase(self, state: dict) -> dict:
        """Model 阶段：在 Spec / Pattern / Data Pipeline 中建模。"""

    async def compare_phase(self, state: dict) -> dict:
        """Compare 阶段：与竞品 / best practice 对比。"""

    async def align_phase(self, state: dict) -> dict:
        """Align 阶段：与 Gate OS 角色、品牌、业务目标对齐。"""

    async def deliver_phase(self, state: dict) -> dict:
        """Deliver 阶段：真正输出到 Spec / 代码 / 发布渠道。"""
```

### 4.3 预期代码位置

- `src/gate_os/workflow_orchestrator.py`

## 5. 与 Project / Client SDK 的接口约定（高层）

> 详细的项目级 SDK 设计见：`../sdk/xiaohongshu-project-sdk.md`。这里只定义 Gate OS 层面，SDK 需要提供哪些输入。

- SDK → Gate OS：Intent Package 必须包含：
  - `task_type`：任务类型（如 `generate_xhs_post` / `run_weekly_plan` 等）；
  - `spec_path`：主输入 Spec（Post / Weekly / Client 等）的路径；
  - `client_slug` / `project_slug`：用于数据与配置查找；
  - `constraints`：LOA 要求、可用工具白名单等。

- Gate OS → SDK：返回结构中至少包含：
  - `status`：成功 / 失败 / 需要人工介入；
  - `outputs`：关键结果摘要（如 note_id / 生成文本 / 更新的 Spec 路径）；
  - `evidence`：可选的证据摘要（为后续复盘准备）。

> 后续如果要扩展到其他项目（微博、抖音等），只要沿用这套接口设计，
> Project SDK 就可以在不改 Gate OS 内核的情况下接入。
