# 小红书内容与标签范式库（Pattern Library）

> 说明：本文件定义「范式」的概念与基本分类，并提供 LaunchX 客户的初始范式样例。  
> 具体实验数据与效果回顾将记录在 Evolution 层的 Experiment Log 中。

## 1. 范式命名与引用规范

- 范式 ID 建议格式：`P-<Type>-<NN>`，例如：
  - 标题范式：`P-Title-01`、`P-Title-02`…
  - 正文结构范式：`P-Body-01`、`P-Body-02`…
  - CTA 范式：`P-CTA-01`…
  - 标签模式：`P-TagMode-01`…（可与 Tag Engine 组合使用）。
- 在 Post Spec 中引用范式时：
  - 使用 ID + 简短描述，如 `P-Title-02 数字清单型标题`；
  - 若是自定义新范式，应在本文件中登记后再使用。

## 2. 标题范式（示例）

### P-Title-01 · 痛点 + 结果型

- 结构：
  - 「你是不是也遇到 X？教你一个 Y 的方法」
- 典型用途：
  - 针对中小团队/个人的效率痛点、选型焦虑；
- 示例（LaunchX）：
  - 「总是选错 AI 工具？3 个方法帮你避开大坑」

### P-Title-02 · 数字清单型

- 结构：
  - 「N 个…让你…」
- 典型用途：
  - 工具清单、方法总结、Best Practices 类内容；
- 示例（LaunchX）：
  - 「3 个 AI 工具，让你的团队效率翻倍」

### P-Title-03 · 对比/踩坑型

- 结构：
  - 「别再这样做了，我已经帮你踩过坑」/「X vs Y，到底谁更适合你？」
- 典型用途：
  - 横评/对比评测、踩坑分享；
- 示例（LaunchX）：
  - 「Claude vs ChatGPT，企业选哪个更省心？」

> 后续可根据真实表现，在 Evolution 层记录每个标题范式的效果（平均曝光/互动率等）。

## 3. 正文结构范式（示例）

### P-Body-01 · 场景-冲突-解决-结果

- 结构：
  1. 场景：讲一个具体使用场景或工作情境；
  2. 冲突/痛点：点出当下的困境或常见错误；
  3. 解决思路：告诉读者大致的解决路径；
  4. 具体步骤：列出 3–5 个可执行步骤；
  5. 结果/反馈：无论真实或预期，告诉读者「值得一试」。

### P-Body-02 · 问题-拆解-清单

- 结构：
  1. 提出问题；
  2. 拆解关键因素（2–3 个）；
  3. 用清单方式依次解决。

## 4. CTA 范式（示例）

### P-CTA-01 · 评论互动型

- 目标：鼓励读者在评论区分享经验或问题；
- 示例话术：
  - 「你在用哪个 AI 工具？在评论区说说看」
  - 「还有哪些好用的工具值得测？评论告诉我」

### P-CTA-02 · 私信咨询型

- 目标：为私域转化/深度沟通引流；
- 示例话术：
  - 「想要完整评测报告，在私信回复【评测】」

## 5. 标签模式范式（Tag Engine 片段）

> 完整标签体系来自 LaunchX SEO 文档，这里抽象出可供引用的「模式」。

### P-TagMode-01 · 保守型（Conservative）

- 结构：
  - 1–2 个品牌标签 + 1–2 个功能标签 + 2–3 个热门标签 + 1–2 个长尾标签
- 适用：
  - 新账号、品牌心智建设期，风险偏好低。

### P-TagMode-02 · 平衡型（Balanced）

- 结构：
  - 2 个品牌标签 + 2 个功能标签 + 2 个热门标签 + 2 个长尾标签
- 适用：
  - 大部分日常内容，兼顾品牌与流量。

### P-TagMode-03 · 进攻型（Aggressive）

- 结构：
  - 2 个品牌标签 + 3–4 个热门标签 + 2 个新兴趋势标签 + 1–2 个长尾标签
- 适用：
  - 核心长文、重磅评测、节点活动，冲击爆款时使用。

## 6. 后续演化与数据驱动

- 每次 Experiment（实验）应记录所用范式 ID + 实验结果；
- Evolution 层的 Experiment Log 负责：
  - 汇总每个范式在不同 Client/行业中的表现；
  - 标记「高表现范式」「待观察范式」「效果欠佳范式」。
- 当某个范式得到足够数据支持或被证伪时，应：
  - 在本文件中更新其描述与推荐场景；
  - 在方法论文档中记录「升级日志」。


## 7. 内容类型范式（Content Archetypes）

> 说明：内容类型范式用于描述「这一条笔记整体在扮演什么角色」，比如是 Gate 解决方案日记，还是行业/分线观察。  
> Claude 在生成/优化 Post Spec 时，可以根据内容类型优先选择合适的标题/正文/CTA/标签范式组合。

### P-Content-01 · Gate 解决方案日记（Gate Solution Diary）

- 典型内容：
  - 真实的客户场景 / 内部试验场景，从「现状 → 问题 → Gate 介入 → 过程 → 结果/复盘」讲清楚；
  - 重点在于展示问题的复杂性和解决过程的可信度，而不是硬性推销产品。
- 建议结构：
  - 标题：
    - 推荐使用 `P-Title-01`（痛点+结果）或 `P-Title-03`（对比/踩坑）；
  - 正文：
    - 推荐使用 `P-Body-01`（场景-冲突-解决-结果）；
  - CTA：
    - 以 `P-CTA-01`（评论互动）为主，视情况轻带 `P-CTA-02`（私信咨询）。
- 标签倾向：
  - 功能/场景标签（如 `#企业AI转型`、`#流程自动化`）；
  - 行业标签（如 `#制造业`、`#SaaS企业`）；
  - 少量热门标签增强曝光（如 `#效率提升`）。
- 主要目标：
  - 建立 Gate/LaunchX 在企业 AI 解决方案上的可信度与专业形象；
  - 自然引出「我们可以帮你做类似的事」，而不是硬广。

### P-Content-02 · 行业 / 分线在干啥（Industry / Line Diary）

- 典型内容：
  - 围绕某个行业 vertical 或内部某一条业务线（如 HR 自动化、财务自动化、小红书代运营），
    讲「最近行业发生了什么」和「我们在这一条线上的观察/实践」。
- 建议结构：
  - 标题：
    - 可用 `P-Title-02`（数字清单型）或「问题/观察型」变体；
  - 正文：
    - 推荐使用 `P-Body-02`（问题-拆解-清单）或对现状/趋势/坑点做分点说明；
  - CTA：
    - 以 `P-CTA-01` 为主，鼓励同行/决策者在评论区交流看法或补充场景。
- 标签倾向：
  - 行业标签（如 `#企业服务`、`#HR科技`、`#财务数字化`）；
  - 话题标签（如 `#AI原生应用`、`#Agent工作流`）；
  - 适度使用品牌标签保证 LaunchX 露出。
- 主要目标：
  - 吸引真正关心该行业/分线的人关注 LaunchX；
  - 为后续更深入的 Gate 解决方案日记和评测内容打基础。
