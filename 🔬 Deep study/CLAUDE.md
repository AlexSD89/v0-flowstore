# 深度研究 CLAUDE 指南

## Phase 0 Checklist
1. 阅读根级与本目录的 `README`、`RULES`，掌握范围与禁区。
2. 确认课题档案：立项背景、假设、预期成果、关键资料。
3. 同步 `memory-bank/support_modules/deep-study/USEME.md`（研究框架、数据脚本、模板）。
4. 核对 `memory-bank/README.md` 中的课题状态与已有洞察。
5. `/spec` 中列出：研究问题、输入来源、验证方式、交付时间、高风险点。

> 初始灵感、访谈速记可暂存 `🤖 AI生成 auto-generated/日期`，需在 24 小时内整理至正式目录。

## 执行流程
| 阶段 | 目标 | 交付 |
| --- | --- | --- |
| 课题设定 | 确认问题边界、假设、评估指标 | 立项文档、资源需求、时间表 |
| 资料整理 | 建立引用索引、数据字典、方法论映射 | 资料清单、引用表、空缺列表 |
| 推演分析 | 构建模型、场景、实验，记录推理链 | 分析笔记、模型说明、可视化草稿 |
| 验证反馈 | 与业务/技术试点，获取数据与反馈 | 验证日志、指标对照、风险清单 |
| 发布归档 | 输出报告/白皮书，更新索引、回写经验 | 最终报告、Summary、后续议题 |

## 方法与工具
- 框架：系统动力学、Second Order Thinking、Scenario Planning、Backcasting 等。
- 数据：使用 `memory-bank/support_modules/deep-study/scripts/*` 执行采集与清洗，记录参数。
- 协作：与知识域共享引用，在业务域建立验证会，还原决策记录。
- 可视化：联动设计域制作关键图表，确保信息传达。
- 自动化：与 `🧩 bmad` 的 Automation Partner 协作，沉淀数据处理与验证脚本。

## 质量守则
- 所有推理需有数据或案例佐证，注明可信度与假设前提。
- 若结论基于外部报告，需记录获取方式、发布时间、作者背景。
- 每个阶段结束提交阶段 Summary，说明进度、风险、下一步计划。
- 研究未完成不得发布对外观点，确保审校完备。
