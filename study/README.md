# Study 域总览

> Study 目录主要存放深度研究草稿、实验性项目与尚未固化的方法论素材，是连接即时探索与正式知识资产的“缓冲区”。

## 📌 定位
- 在知识域正式归档前，存放需要进一步验证的研究成果、实验项目、临时数据。
- 支撑 `🟣 knowledge`、`🚀 Launchx业务服务` 等域的趋势洞察、案例分析和方案制定。
- 记录实验日志、数据处理脚本，形成可追溯的研究路径。

## 🗂️ 目录结构参考
| 子目录 | 用途 | 归档策略 |
| --- | --- | --- |
| `docs/`、`docs 1/`、`v2/` 等 | 长期研究草稿、案例剖析 | 验证后迁移到 `🟣 knowledge` 对应目录 |
| `specs/` | 深度研究 `/spec` 草案、实验计划 | 执行完毕迁移至研究成果或方法论 |
| `02_业务架构/` | 行业/业务架构研究 | 产出稳定结论后同步知识域或业务域 |
| 单体 Markdown 报告 | 已完成但待复审的研究报告 | 通过审核后迁往 `🟣 knowledge/03_研究报告` |

## 🧭 写作与输出要求
- **信息来源**：以本地调研数据、访谈记录、实验结果为主；引用外部资料时需标注出处及验证状况。
- **输出形态**：研究笔记、实验记录、草稿报告、数据脚本。重要结论需在迁移前补齐 frontmatter 与验证说明。
- **迁移策略**：草稿在 7 日内决定去向（归档 / 补充 / 删除）；正式归档后从 Study 中移除或加注“已迁移”说明。
- **AI 生成物**：如使用 AI 生成研究初稿，需在文件头部注明来源，并在 24h 内完成人工校对。

## 🔗 协同建议
- 与知识域协作：一旦形成稳定结论或方法论，应迁移至相应目录，并更新互链（方法论、趋势、结论）。
- 与业务域联动：将研究结果转化为客户方案或市场素材时，需同步回写使用情况。
- 与工具/自动化域配合：研究过程中的脚本或验证流程，可沉淀到 `🧰 tools` 或 `🧩 bmad` 形成复用能力。

## ✅ 日常维护清单
```
[ ] 每周清理无主或过期草稿，标记“已归档/待补/弃用”
[ ] 更新研究计划的执行状态，保持 specs/ 与实际进度一致
[ ] 将完成的研究迁移至知识域，并在 Summary 写明互链更新
[ ] 将可复用脚本登记到 memory-bank/support_modules/ 对应 USEME
```

> Study 目录是 LaunchX 的“深度研究工作台”。请遵循以上约定，确保草稿资产安全、可追溯，并能顺畅迁移到正式知识库。
