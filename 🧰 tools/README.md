# 🧰 Tools 域总览

> 本目录沉淀可直接复用的工具链、脚手架与自动化模板，是业务域、技术域、方法论输出之间的“工具集散地”。所有内容以本地仓库可验证的代码、脚本和配置为准。

## 📌 定位与范围
- 为项目/业务提供可落地的工具与脚手架（如 Pocketcorn、TradingAgents 等）。
- 维护工具的安装、使用、回滚说明，确保跨域团队可以快速集成。
- 配合 `🧩 bmad`、`🧠 Launch-X Skills生态系统` 将高频需求沉淀为可自动化的能力模块。

## 🗂️ 目录结构概览
| 子目录 / 文件 | 说明 |
| --- | --- |
| `pocketcorn4.2/` | 智能工具开发框架（示例项目、生成器、验证器） |
| `tradingagents-enhancement/` | AI 增强的交易代理工具集 |
| `CLAUDE.md` | 工具域的 Claude 协作指引（待对齐当前规范） |
| *(待补充 README)* | 具体项目下需补充 README/使用说明/回滚指南 |

## 🧭 写作与信息来源规范
- **信息来源优先级**：本地代码与脚本 > 执行日志 > 经过验证的外部资料。引用外部方案时，必须在 `/spec` 评估并写明适配与验证步骤。
- **输出内容**：工具定位、依赖、安装方式、验证命令、回滚策略、适用场景；必要时附最小示例。
- **禁止事项**：禁止仅凭设想描述工具能力；禁止缺失验证步骤或回滚说明；禁止复制外部 README 而未结合本地代码。
- **引用规则**：文件内引用路径使用 `path:line` 或子 README 标题，确保可追溯。所有更新须同步 `📖README-LaunchX系统总体指南.md` 的配套表及目录索引。

## 🤝 协同接口
- **技术域 (`💻 技术开发/`)**：在项目中引用工具时需回写实践经验，发现问题时反馈到工具域并更新文档。
- **自动化域 (`🧩 bmad/`)**：高频任务可先在工具域验证，再沉淀到 bmad 形成 Agent 脚本。
- **技能域 (`🧠 Launch-X Skills生态系统/`)**：若工具具备可复用的技能能力，需同步更新 Skills 模板与调用示例。
- **系统管理 (`🛠️ 系统管理/`)**：关键配置/脚本需在 memory-bank 备案，保持环境一致。

## ✅ 维护清单
```
[ ] 每次工具更新后补充 README / CHANGELOG / 回滚方案
[ ] 同步验证命令到支持的自动化脚本（如 package.json、Makefile 等）
[ ] 将高频使用指引回写至 memory-bank/support_modules/ 对应 USEME
[ ] 每季度复查工具有效性，废弃或迁移老旧工具并在 README 记录
```

> 如需新增工具，请先提交 `/spec` 说明背景、依赖、验证计划，再在工具域创建子目录并按照上述要求补全文档。完成后在 Summary 标注“tools 域已更新”，便于联动目录同步。
