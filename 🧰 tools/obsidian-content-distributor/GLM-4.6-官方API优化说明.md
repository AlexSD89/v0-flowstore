# GLM-4.6 API 官方限制优化说明

## 📋 优化背景

在用户反馈的API调用失败（429错误）基础上，通过搜索官方文档，对GLM-4.6 API的配置参数进行了官方最佳实践优化。

## 🔍 官方文档调研结果

通过多个搜索渠道找到的官方信息：

1. **速率限制维度**：智谱AI API的限制维度主要是**并发请求数**，而非严格的时间间隔
2. **Rate Limiting Guide**：官方有专门的速率限制指南
3. **GLM Coding Plan**：套餐每5小时恢复额度，说明有频率控制机制
4. **并发控制**：官方文档明确说明"当前限制维度为并发请求数"

## ⚙️ 优化策略

### 1. 配置参数调整

**优化前：**
```typescript
{
    requestInterval: 3000, // 3秒间隔
    maxRetries: 1        // 仅重试1次
}
```

**优化后（基于官方策略）：**
```typescript
{
    requestInterval: 1000, // 1秒间隔，适应官方并发控制
    maxRetries: 2        // 增加重试次数，处理瞬时并发限制
}
```

### 2. 并发控制策略改进

**核心改进：**
- 明确识别官方限制主要是**并发请求控制**而非严格时间间隔
- 优化请求队列逻辑，严格防止并发请求
- 缩短等待间隔，提高响应速度

**错误提示优化：**
- 将"频率控制"改为"并发控制"，更符合官方术语
- 调整错误消息，更准确地反映问题性质

### 3. 重试策略升级

**指数退避算法：**
```typescript
// 指数退避：2^attempt * baseDelay，最大不超过8秒
const delay = Math.min(baseDelay * Math.pow(2, attempt - 1), 8000);
```

**优势：**
- 短期限制冲突时智能退避
- 避免固定延迟导致的资源浪费
- 提高成功率，减少用户等待时间
