# 知识管理｜知识治理与规则体系方法论

> **核心问题**：如何在 AI 协作环境中让知识资产保持“可追溯、可信赖、可增值”，并与业务节奏同频迭代。

## 1. 治理目标与指标

| 目标 | 指标 | 定义 | 目标值 |
| --- | --- | --- | --- |
| 数据可信 | 数据源评级覆盖率 | 完成评级的数据源 / 全部数据源 | ≥ 95% |
| 规则可执行 | 有效规则合规率 | 被调用规则中通过审核 / 总调用 | ≥ 92% |
| 知识复利 | 反脆弱快照闭环率 | 触发异常后完成回写 / 总异常 | ≥ 85% |
| 行动高效 | 行动计划达成率 | 行动项按期完成 / 总行动项 | ≥ 90% |

> 指标定义沿用 20250823 历史稿，结合 2025-Q3 运营经验更新目标值。

## 2. 数据与内容治理（Data Governance）

### 2.1 数据源评级流程
1. **盘点**：Collect 阶段梳理数据源（系统、文件、Session）。
2. **评级**：按 `来源可信度 × 更新频率 × 权限敏感度 × 业务价值` 打分，采用 1-5 星评级。
3. **准入**：评级 <3 的数据源需在 `/spec` 记录补救措施，未通过前不得进入知识库。
4. **监控**：建立月度复核任务，自动提醒数据负责人。

### 2.2 内容归档策略
- 采用“三层盒”模型：操作手册（即用）、方法论（框架）、研究档案（追溯）。
- 归档前必须补齐 frontmatter、引用来源与 TODO；未补齐的输出回退至 Collect 阶段。
- Archive 记录同步 memory-bank，并在 Summary 标注互链状态。

## 3. 规则体系构建（Rule Management）

### 3.1 规则生命周期
| 阶段 | 触发动作 | 关键产出 |
| --- | --- | --- |
| Draft | Collect → Model，形成初稿 | 规则草案、引用依据 |
| Review | Compare → Align，域负责人审批 | 审批记录、风险说明 |
| Publish | Deliver，正式执行 | 发布公告、技能/工具更新 |
| Retire | Archive，低效或过时 | 退役说明、替代方案 |

### 3.2 规则引用规范
- 每条规则包含 `触发条件 / 执行动作 / 验证方式 / 回滚`，同一主题的规则集中存放。
- 引用时需在 Summary 或 `/spec` 标注规则 ID，便于追踪使用频率。
- 通过 memory-bank 的 `rules_index.json` 维护最新列表，自动化脚本每周比对。

### 3.3 规则使用仪表
- 指标：引用次数、引用成功率、触发异常数。
- 采集：BMAD 日志 + Git 钩子。
- 回溯：异常>3 次的规则自动进入“改进池”，通过 Compare 工作坊修订。

## 4. 反脆弱知识系统（Resilience Loop）

### 4.1 异常即资产
- 异常触发 → 记录事实（时间、责任人、上下文） → 在 `/spec` 添加修正项。
- 通过 `异常→分析→规则更新→回写` 四步闭环，将“噪音”转化为规则或知识。
- 反脆弱快照写入 `Archive/反脆弱日志/<date>.md`，每月由 Memory Curator 整理趋势。

### 4.2 人机协作模式
- AI 协作者负责初步归纳与分类，人类审核补充因果与责任。
- 遇到指令二义性，回到 Collect 阶段重写指令；必要时更新 `AGENTS.md`。
- 行动计划采用“两层责任制”：执行人 + 监督人，同时设置过期提醒。

## 5. 行动计划与执行追踪

### 5.1 行动计划模板
```
行动项：<描述>
目标值：<指标 or 结果>
负责人 / 监督人：<name> / <name>
截止时间：YYYY-MM-DD
验证方式：命令 / 报告 / 数据仪表
互链：README / memory-bank / Summary 链接
```

### 5.2 执行流程
1. Collect：梳理 backlog → 优先级评估（价值 × 紧急度 × 风险）。
2. Align：冻结行动项，指定责任人与监督人。
3. Deliver：执行并记录验证；达成后更新仪表并归档。
4. Archive：评估成效，决定是否沉淀成规则或方法论。
