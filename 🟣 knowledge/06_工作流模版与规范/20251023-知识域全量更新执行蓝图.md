# 知识域全量更新执行蓝图

## 1. 目标与衡量
- **覆盖面**：三周内完成 🟣 knowledge 全目录巡检与更新，确保关键资产状态明确。
- **质量线**：frontmatter 必填字段填充率 ≥ 95%，`status` / `last_update` 与实际进展一致。
- **效率线**：通过自动化巡检工具，将手工盘点时间压缩至 < 30 分钟。
- **追踪机制**：在 `09_周报月报` 中建立“知识域治理”专栏，记录本周动作与阻塞项。

## 3. 三阶段行动路径

### Phase A · 基线清点（T+2 天）
1. **巡检记录**：运行 `knowledge_audit.py`，在周报中抄写核心指标。
2. **目录负责人确认**：从 `00_模块引导系统/@...模块视图.md` 提取 Owner，建立责任表。
3. **优先队列**：锁定以下子目录优先处理：
   - `07_市场项目档案`：高缺口 & 高复用率。
   - `03_研究报告`：对外材料引用频繁。
   - `05_方法论中心`：作为规范源，需要先完善。
4. **问题分类**：将巡检结果同步到共享任务表（建议格式：Path | 缺口类型 | Owner | 截止日期）。

### Phase B · 内容现代化（T+10 天）
1. **Frontmatter 批量补齐**：按目录分配任务，使用模板快速补充必填字段；同期校正 `status`、`last_update`。
2. **版本合并 & 清理**：
   - 对 `*_temp` / `*_updated` / `*_final` 进行比对，保留单一权威版本，其余标记或删除。
   - 将过期数据（>180 天未更新且无业务价值）转入归档或明确说明。
3. **方法论对齐**：核查 `05_方法论中心` 与 `06_工作流模版与规范`，确保引用指向最新版，删除冗余旧稿。
4. **引用闭环**：在补完内容时同步更新 `related` 字段，建立跨目录索引。

### Phase C · 持续治理（T+20 天）
1. **自动化嵌入流程**：将 `knowledge_audit.py` 加入周一例行任务；必要时将 JSON 输出接入任务看板。
2. **指标看板**：提取脚本 JSON 中的 `missing_field_counts`、`directory_stats`，绘制趋势图（建议使用 Quickchart）。
3. **质量门槛**：未达成 frontmatter 要求的文档禁止转入 `status: published`，在 README 中维护“黑名单”。
4. **复盘沉淀**：每阶段结束在 `09_周报月报` 登记成果、遗留问题与下阶段计划。
