# 🔄 系统迭代学习 · 模块视图

## 模块使命
- 监控知识生产全链路的质量与效率，构建可复用的改进机制。
- 将数据、流程、指标、经验统一回写到知识域，驱动方法论与工具演进。

## 资产地图
| 领域 | 主路径 | 功能 |
| --- | --- | --- |
| 数据底座 | `02_分析与洞察/00_数据库/` | 结构化事实、标签、指标；供分析与图谱使用 |
| 流程与模板 | `06_工作流模版与规范/` · `05_方法论中心/📚 知识管理方法论/` | 流程手册、Checklist、最佳实践 |
| 反馈记录 | `09_周报月报/` · `d_迭代优化和学习/` | 周期复盘、问题追踪、迭代日志 |
| 自动化工具 | `memory-bank/support_modules/knowledge/tools/` | 巡检脚本、指标计算、批处理工具 |
| 标签与索引 | `🟣 knowledge/🛠️@ai潜在学习项目总览.md` · `02_分析与洞察/TEMPLATES.md` | 标签体系、字段定义、索引管理 |

## 工作闭环
1. **采集**：原始资料进入 `01_Inbox`，跟随巡检清单 24 小时内迁移。
2. **分析**：在 `02_分析与洞察` 执行五通道流程，更新数据库与洞察文档。
3. **输出**：成熟内容进入 `03_研究报告`、`07_市场项目档案`、`08_知识传播与品牌`。
4. **监测**：通过 `knowledge_audit.py`、周报指标和项目复盘监控质量。
5. **回写**：形成的经验写入 `05_方法论中心` 与 `06_工作流模版与规范`，同步更新 USEME。
6. **复盘**：在 `09_周报月报` 记录问题、改进动作，必要时创建专项迭代任务。

## 复查重点（2025-10-23）
- `02_分析与洞察/00_数据库` 存量文档缺乏 frontmatter 与字段定义，需要补齐并建立索引表。
- `d_迭代优化和学习` 目录目前仅有概要，需补写近期迭代日志与行动项完成度。
- `knowledge_audit.py` 报告显示大量文档缺失 `related`/`impact` 字段，需列入 Phase B 批量修复。

## 指标框架
- **数据维度**：完整率 ≥ 95%，交叉验证通过率 ≥ 90%，更新时间默认 ≤ 30 天。
- **流程维度**：关键模板使用率 ≥ 85%，巡检覆盖率（周）= 100%，异常关闭率 ≥ 80%。
- **知识维度**：复用率（被引用次数/总产出）持续提升，方法论更新至少月度一次。
- **反馈维度**：周报问题在次周期明确责任与进度，关键风险纳入专案追踪。

## 协同关系
- **技术与自动化团队**：对接 `🧩 bmad`，将高频迭代项转化为脚本或守护任务。
- **业务与投资团队**：提供实际项目反馈，帮助修订方法论与指标。
- **品牌团队**：同步传播效果，反向推动知识结构调整。
