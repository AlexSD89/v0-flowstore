# 07_市场项目档案 · 档案管理规范

版本：2025-10-11 · 维护：Market Desk

## 1. 目录定位
本目录用于保存市场/企业/竞品相关的结构化档案，为业务交付、投资评估、趋势分析提供基础数据。与 `03_研究报告` 不同，此处重在“资料库”而非叙事性报告。

## 2. 档案类型
| 类型 | 说明 |
| --- | --- |
| `行业档案` | 行业概览、规模、增长、关键参与者 |
| `公司档案` | 公司基本信息、产品矩阵、融资、团队 |
| `案例档案` | 成功/失败案例、运营策略、关键数据 |
| `客户画像` | 客户细分、痛点、需求场景 |

可按类型或行业建立子目录，但需在 README 中维护索引表。

## 3. frontmatter 模板
```yaml
---
title: "20251005-行业名-档案"
owners: ["调研人"]
status: published | review | draft
last_update: 2025-10-05
category: industry | company | case | customer
region: global | mainland_cn | us | ...
related: ["🟣 knowledge/02_分析与洞察/...", "🚀 Launchx业务服务/..." ]
source: ["[[🟣 knowledge/01_Inbox/...]]", "公开数据库"]
impact: "支撑 AI 转型咨询及投资评估"
---
```

## 4. 内容结构建议
### 行业档案
1. 行业概览（规模、增长率、生命周期）
2. 价值链 & 关键角色
3. 趋势与驱动因素
4. 风险与挑战
5. 代表公司/案例

### 公司档案
1. 公司简介（成立时间、团队、融资）
2. 产品与服务
3. 商业模式与收入结构
4. 技术/数据能力
5. 竞争优势与风险
6. 参考资料/链接

## 5. 质量要求
- 数据需注明来源与日期；引用 `01_Inbox` 或外部链接。
- 数字指标（收入、用户数、融资）尽量保留原始文本或截图路径。
- 若信息不确定，使用 `status: review` 并注明待验证项。
- 更新后在 Summary 中说明“市场档案已更新”，方便团队同步。

## 6. 与其它目录关系
- `03_研究报告`：用于深度分析；可引用本目录作为数据支撑。
- `🚀 Launchx业务服务`：客户方案、案例需引用档案内容。
- `memory-bank/`：记录最新档案以便快速检索。

## 7. 推荐工作流
1. 从 `01_Inbox` 获取资料，按照模板整理档案。
2. 交叉验证关键数据，标注来源。
3. 与业务团队确认是否需要同步到对外材料。
4. 更新 README 索引及相关 USEME 文档。

保持项目档案最新、可靠、可追溯，能显著提升业务交付与投资、咨询效率。***
