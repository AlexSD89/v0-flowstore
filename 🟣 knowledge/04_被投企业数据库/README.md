# 04_被投企业数据库 · 档案体系

版本：2025-10-11 · 维护：Investment Desk

## 1. 目录定位
保存被投企业及重点目标公司的档案，用于投资评估、后续跟踪和项目复盘。与 `07_市场项目档案` 区别在于：此处聚焦“己方投资/重点关注企业”的持续数据。

## 2. 目录结构
| 子目录 | 说明 |
| --- | --- |
| `AI创意与内容生成/` | 赛道分类下的企业档案 |
| `AI教育/` | …… |
| `企业服务/` | …… |
- 可按行业或基金策略扩展子目录，保持 README 中的索引同步更新。
- `项目报告生成规则.md`：归档格式、字段定义，可在更新时一起修订。

## 3. 档案模板
```yaml
---
title: "20251010-公司名-档案"
owners: ["调研人", "维护人"]
status: active | monitor | exited
last_update: 2025-10-10
industry: "行业分类"
region: "区域"
stage: seed | A | B | growth | IPO
related: ["🟣 knowledge/02_分析与洞察/…", "🟣 knowledge/03_研究报告/…"]
source: ["[[🟣 knowledge/01_Inbox/markdown/...]]", "公开数据库"]
impact: "评估投资机会 / 跟踪运营指标"
---
```

### 3.1 内容结构建议
1. 基本信息（成立时间、团队、融资）
2. 产品与服务
3. 商业模式与指标（收入、用户、留存）
4. 技术与数据能力
5. 投资亮点 / 风险
6. 里程碑事件（时间线）
7. 附录：引用、附件、脚本说明

## 4. 维护规范
- 更新档案后，在 Summary 标注“被投企业数据库已更新”，并同步到 `memory-bank` 或周报。
- 对于退出或失效项目，可将 `status` 设置为 `exited` 并移动到 `archive/` 子目录。
- 确保所有数字指标附上来源与日期，便于验证。
- 与 `03_研究报告`、`07_市场项目档案` 互通：报告引用企业数据时需链接到此处档案。

## 5. 自动化与工具
- 推荐使用 `memory-bank/support_modules/knowledge/USEME.md` 中的脚本整理数据。
- 可通过 MCP (`tavily-remote-mcp`、`jina-ai`) 抓取最新公开信息，归档至 `01_Inbox` 后按流程迁移。

维护好此数据库可显著提升投资跟踪与决策效率。***
