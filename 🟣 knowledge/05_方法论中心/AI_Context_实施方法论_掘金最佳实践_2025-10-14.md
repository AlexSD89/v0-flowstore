### 第二阶段：跨仓库集成

#### 编辑器配置 (.cursorrules)
```yaml
# .cursorrules 标准配置
严格遵循工作流程：
收到任务 → 检查 Rules → 分析项目结构 → 执行

检查该项目是否为 monorepo 架构：
如果为 monorepo 子仓库，则向上查看父仓库和 support_modules 的指导文件

优先级控制：
1. 检查根目录 CLAUDE.md 了解规则
2. 读取相关包的 USEME.md 了解能力
3. 优先复用 support_modules 下的能力

```

#### 路径映射机制
```yaml
AI 索引流程:
1. AI 读取 .cursorrules，知道要检查父仓库
2. 通过根仓库 CLAUDE.md 获取全局规范
3. 根据"文档地图"索引各包的 USEME.md
4. 在生成代码时优先使用公共库的能力
```

### 第三阶段：最佳实践落地

#### ✅ 推荐的实践模式

##### 1. 精简文档内容
- **只写用法，不写原理** - 让 AI 当"用户"，不当"维护者"
- **示例展示最佳实践** - 提供完整、正确的代码示例
- **约束精简化** - 5条核心约束 + 示例引导

##### 2. 强制导入规范
```javascript
// ✅ 正确: 使用具体文件路径
const { BMADNativeTasks } = require('/Users/dangsiyuan/Documents/obsidion/launch x/🧩 bmad /bmad-core/src/bmad-native-tasks.js');

// ❌ 错误: 避免 barrel 导入
// import { analyzeMarket, assessRisk } from 'bmad-core';  // 禁止
```

##### 3. 参数表格式优化
```markdown
| 参数名 | 类型 | 默认值 | 必填 | 说明 |
|--------|------|--------|------|------|
| query | string | - | ✅ | 分析主题描述 |
| dimensions | array[] | ['basic'] | ❌ | 分析维度列表 |
| timeout | number | 30000 | ❌ | 超时时间(毫秒) |
```

#### ❌ 避免的反模式

##### 1. 文档过于详细
- **错误**: 在 USEME.md 中写详细实现原理和设计思路
- **结果**: AI 被"误导"，尝试"改进"现有实现
- **正确**: 只写用法，让 AI 专注于使用

##### 2. 简化示例的误导性
- **错误**: 使用简化的错误处理示例
- **结果**: AI 照搬简化写法，忽略错误处理
- **正确**: 展示完整的最佳实践示例

##### 3. 过度约束
- **错误**: 制定 20+ 条详细规范
- **结果**: AI 被"畏首畏尾"，生成代码过于保守
- **正确**: 精简为 5 条核心约束，通过示例引导
