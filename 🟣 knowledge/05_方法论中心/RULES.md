## 🚫 严禁操作 (研究红线)

### 1. 研究诚信约束
- **❌ 禁止伪造数据** - 严禁编造或篡改研究数据
- **❌ 禁止剽窃内容** - 必须注明信息来源和引用
- **❌ 禁止误导性结论** - 基于数据得出客观结论
- **❌ 禁止未经验证的断言** - 重要结论必须有充分证据

### 2. 数据来源约束
- **❌ 禁止使用未授权数据** - 遵循数据使用条款和版权
- **❌ 禁止绕过付费墙** - 尊重知识产权和付费内容
- **❌ 禁止过度采集数据** - 遵循网站robots.txt和使用条款
- **❌ 禁止存储敏感个人信息** - 遵循隐私保护法规

### 3. 方法论使用约束
- **❌ 禁止曲解方法论** - 按照既定框架使用方法论
- **❌ 禁止跨级误用** - 4层分级体系不得混用
- **❌ 禁止跳过质量检查** - 必须通过BMAD质量控制
- **❌ 禁止忽略验证步骤** - 多源验证不可省略

## ⚠️ 重要限制 (操作边界)

### 1. 搜索策略限制
```yaml
单次搜索主题数: 1个主要主题
并发搜索通道数: 最多5个
搜索结果数量: 每通道最多20条
搜索时间限制: 单次搜索最多10分钟
```

### 2. 信息来源限制
```yaml
最低来源数量: 至少3个独立来源
权威来源比例: >60%来自权威机构
信息时效性: 80%信息为近6个月内
语言要求: 中英文来源均衡
```

### 3. 分析深度限制
```yaml
报告最大长度: 5000字
分析层级: 最多4层深度
结论数量: 每个主题不超过5个主要结论
预测范围: 最多预测未来24个月
```

## 🔬 研究质量标准

### 1. 信息质量要求
```yaml
准确性标准: >95%关键事实准确
完整性标准: 覆盖主题的主要方面
时效性标准: 信息与当前时间相关
权威性标准: >70%来自权威来源
```

### 2. 分析质量要求
```yaml
逻辑一致性: 100%内部逻辑自洽
证据充分性: 每个结论都有充分证据
客观性标准: 区分事实和观点
创新性要求: >20%原创洞察和观点
```

### 3. 实用性要求
```yaml
可操作性: 结论具有实际指导意义
可行性评估: 建议具有现实可行性
价值评分: >4.0/5.0实用价值
应用场景: 明确的应用场景和建议
```

## 📋 研究流程规范

### 1. 研究启动阶段
```yaml
主题确认: 明确研究目标和范围
方法论选择: 选择合适的4层方法论
资源评估: 评估所需时间和资源
合规检查: 确认研究活动合规性
```

### 2. 信息收集阶段
```yaml
5通道搜索: 并行执行5个搜索通道
来源筛选: 按权威性和时效性筛选
数据验证: 多源交叉验证关键信息
质量评估: BMAD质量评分和排序
```

### 3. 分析整合阶段
```yaml
信息分类: 按主题和重要性分类
模式识别: 识别关键模式和趋势
洞察提取: 提取深层洞察和规律
结论验证: 验证结论的可靠性
```

### 4. 成果输出阶段
```yaml
报告撰写: 按标准模板撰写报告
质量审核: 多维度质量检查
格式规范: 符合文档格式要求
归档管理: 按分类规则归档
```

## 🔐 数据保护与隐私

### 1. 个人信息保护
- 收集个人信息必须有明确目的
- 个人信息使用必须获得同意
- 个人信息存储必须加密保护
- 个人信息保留必须有时限

### 2. 数据安全要求
- 研究数据必须定期备份
- 敏感数据必须访问控制
- 数据传输必须加密保护
- 数据删除必须彻底清除

### 3. 合规性要求
- 遵循GDPR等数据保护法规
- 遵循行业特定的合规要求
- 定期进行合规性审计
- 建立数据保护应急预案

## 🚨 异常处理机制

### 1. 研究异常处理
```yaml
信息不足: 扩大搜索范围或调整策略
来源冲突: 标记冲突并寻求更多信息
质量不达标: 重新搜索或补充验证
时效性差: 寻求更新信息来源
```

### 2. 技术异常处理
```yaml
搜索失败: 切换备用搜索策略
工具异常: 使用替代工具或手动操作
数据异常: 标记异常并继续其他分析
系统超时: 分批处理或优化算法
```

### 3. 合规异常处理
```yaml
权限问题: 停止相关操作并申请权限
版权争议: 移除争议内容并寻找替代
隐私风险: 立即删除相关数据
合规质疑: 暂停研究并寻求专业意见
```
