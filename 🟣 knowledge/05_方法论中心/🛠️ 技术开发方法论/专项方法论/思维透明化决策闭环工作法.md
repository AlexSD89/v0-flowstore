# 思维透明化决策闭环工作法

> 目标：让所有复杂任务的推理链条、方案选择与回写轨迹可解释、可审计、可复用。

## 1. 适用范围
- Level M / L 任务，或任意涉及跨域依赖、方案评估、风险研判的活动。
- Claude / Codex / 多 Agent 在 Collect 阶段识别到“信息不足、方案不唯一、影响面广”时，应立即切换到此工作法。

## 2. 六阶段流程（Collect → Model → Compare → Align → Deliver → Archive）
| 阶段 | 关键问题 | 产出物 | 校验点 |
| --- | --- | --- | --- |
| **Collect** | 目标是什么？有哪些约束/上下文/依赖？ | 事实清单、缺口责任人、初步风险列表 | 引用路径是否准确？缺口是否标注？ |
| **Model** | 现状如何分解？有哪些驱动因素与假设？ | 思维画布：问题拆分、假设、推理链 | 推理链是否自洽？假设是否有依据或缺口标注？ |
| **Compare** | 有哪些可选路径？优劣与风险？如何验证？ | 方案对比表：至少 2 个候选方案 + 选择理由 + 验证策略 | 是否说明放弃方案的原因？验证方式是否可执行？ |
| **Align** | 需要谁确认？信息是否完整？ | 对齐稿：目标 / 方案 / 风险 / TODO 清单 | 对齐对象、依赖、回滚是否明确？ |
| **Deliver** | 如何执行与验证？如何同步日志？ | `/spec`、`/plan`、执行记录、验证日志 | 执行是否遵循计划？验证是否覆盖关键风险？ |
| **Archive** | 如何回写知识与互链？开放问题如何跟踪？ | Summary（含引用）、README / memory-bank 更新、开放问题列表 | 互链是否闭环？开放问题是否分配责任人？ |

> **工具提示**：Model 阶段可使用表格、要点列表或分层节点；Compare 阶段至少输出“推荐 vs 备选”对比；Archive 阶段必须同步到相关 README / memory-bank。

## 3. 思维深度分级标准
| 任务等级 | 思维展示要求 | 最少输出 | 补充说明 |
| --- | --- | --- | --- |
| **Level S** | 说明核心判断依据与潜在风险 | 结论 + 关键依据 + 风险提示 | 若结论依赖资料，需标注来源；无对比需求。 |
| **Level M** | 显式列出假设、候选方案与验证策略 | 思维画布 + 方案对比表 + 验证计划 | 至少 2 个候选方案，说明取舍与风险缓解。 |
| **Level L** | 完整推理链、方案对比、风险矩阵、回滚 | 思维画布 + 方案对比 + 风险/回滚矩阵 + `/spec` | 必须输出测试脚本/评估指标，并在 Archive 阶段回写互链。 |

## 4. 检查清单
- [ ] Collect：引用与缺口标注齐备，未确认信息留在对话或 `/spec`。
- [ ] Model：问题拆分、假设、推理链以结构化方式输出。
- [ ] Compare：至少两个方案 + 优劣 + 风险 + 验证策略；说明推荐理由。
- [ ] Align：确认目标、方案、风险、TODO 与责任人。
- [ ] Deliver：遵循 `/plan` 执行，记录验证日志与回滚策略。
- [ ] Archive：Summary 使用 `Summary / Testing / Next Steps`；更新 README / memory-bank；开放问题列入后续计划。

## 5. 与现有规范的衔接
- `AGENTS.md`：Collect/Align/Deliver 流程升级为六阶段；执行端在 Align 前必须提交 Model + Compare 产出。
- `CLAUDE.md`：分析端负责引导 Model / Compare 输出，并在 Align 阶段审查合理性。
- `RULES.md`：将“测试先行 + 互链回写”扩展为“思维透明 + 方案对比 + 验证 + 回写”硬性要求。

## 7. 后续迭代方向
- 引入可视化思维画布模板（Mermaid、Figma 等）以提升 Model 阶段效率。
- 结合 `🧩 bmad` 自动化，生成方案对比与风险矩阵半自动草稿。
- 为常见任务类型（架构、流程优化、知识整理）制作专属 Compare 清单。

落实本工作法，可在不牺牲执行速度的前提下，提升决策透明度、方案可解释性与知识复用效率。
