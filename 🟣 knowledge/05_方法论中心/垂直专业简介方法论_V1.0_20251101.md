# 垂直专业简介方法论

> **目的**：确保每个业务域都有“可快速理解、可落地引用”的垂直专业简介，满足方法论中心的“垂直专业化”要求[[../RULES.md:27-33]]，并为 Phase 0 / Level S 任务提供高纯度背景材料[[../USEME.md:20-44]]。

## 1. 适用范围
- **对象**：七大业务域（投资决策、业务服务、技术开发、产品设计、知识管理、品牌传播、深度研究）及后续新增垂直域。
- **任务级别**：
  - **Level S（直接对话）**：快速共享域内价值主张、关键指标。
  - **Level M（搜索/MCP）**：作为 Collect 阶段的域背景输入，指导信息检索。
  - **Level L（结构化执行）**：在 /spec 中引用简介，明确垂直域目标与风险边界。
- **产出类型**：Markdown 文档，默认位置 `🟣 knowledge/05_方法论中心/<领域>/专项方法论/`，命名为 `领域_垂直专业简介_VX.Y_YYYYMMDD.md`。

## 2. 产出结构（模板）
每份垂直专业简介应覆盖以下段落：
1. **域定位**：一句话阐明该垂直域的核心价值、服务对象、商业边界。
2. **核心痛点 & 价值命题**：列出 3-5 个高频痛点与对应解决路径。
3. **方法论支撑**：引用现有专项方法论/归档稿件，说明可复用的框架[[../README.md:210-236]]。
4. **关键指标 & 目标值**：列出衡量垂直域成效的 3 项以上指标（可引用现有 KPI 表述）。
5. **典型场景 / 案例**：提供 2-3 个业务情境（内部案例或归档记录），说明落地方式。
6. **互链导航**：列出与该垂直域相关的 README、RULES、归档资料、memory-bank、Skills 等路径。
7. **维护策略 & TODO**：明确更新频率、责任人、未完成研究或数据缺口。

> 可在末尾附上可复用提示词片段、常用数据源、验证 Checklist 等辅助材料。

## 3. 工作流程（Collect → Model → Compare → Align → Deliver → Archive）

### 3.1 Collect｜资料收集
- 从 `专项方法论/` 中的 archived 文档收集该垂直域的旧稿（案例、流程、指标等），整理可复用要素[[../README.md]]。
- 检索 2025-10-28 新版专项方法论、研究报告、市场档案，确保简介引用最新成果[[../USEME.md:36-44]]。
- 拉取业务、产品、技术等域负责人现有对外简介或 Pitch Deck，识别语言风格与差异。

### 3.2 Model｜提炼结构
- 采用《思维透明化决策闭环工作法》拆解：问题空间、假设、证据、结论[[🛠️ 技术开发方法论/专项方法论/思维透明化决策闭环工作法.md:1]]。
- 形成草稿目录，标注每个段落的来源、验证方式与缺口责任人（如需外部数据，使用 `TODO｜待补充 + 来源`）。

### 3.3 Compare｜对比校验
- 至少对比两份历史资料（旧稿 vs 新稿、内部 vs 外部介绍），列出保留/更新/淘汰项。
- 检查指标口径是否与 `README` 中发表的目标一致；若存在冲突，优先保留最新策略[[../README.md:210-236]]。
- 若简介将用于对外传播，需在 Compare 阶段标注法律、品牌、隐私等合规风险。

### 3.4 Align｜共识确认
- 与垂直域负责人/内容 owner 对齐“三要素”：核心价值、指标、案例。
- 记录共识结果及回滚策略（如简介投放后反馈不佳，回到旧版本或归档补充）。
- Align 通过后，更新 `/spec` 或 Summary，准备 Deliver。

### 3.5 Deliver｜成稿与验证
- 依照模板完成正文。
- 自检 Checklist：
  - Frontmatter 完整（title/owners/status/last_update/tags/category/layer/related/source/impact/version）。
  - 引用使用绝对路径或 README 段落，并说明对决策的影响[[RULES.md:92-104]]。
  - 指标、案例均有来源或备注 `TODO`。
  - 提供最小化验证：如与业务 owner 的确认记录、指标来源链接等。
- 如涉及 AI 生成内容，先暂存 `🤖 AI生成 auto-generated/YYYYMMDD/` 并在 24h 内迁移[[RULES.md:148-190]]。

### 3.6 Archive｜互链与更新
- 更新 `README.md` 的目录示例，确保新增简介被列入导航。
- 在 `mapping.md` 中记录新文档状态（新建/更新/归档）。
- 如果简介引用了 memory-bank 或 Skills 资源，更新对应索引。
- 将旧版本移入 `archive/YYYYMMDD/`，并维持版本号（v1.1、v1.2 等）。

## 4. 数据与引用要求
- **必备素材**：业务 KPI（收入、转化、满意度等）、核心产品/服务清单、典型客户或项目案例。
- **引用优先级**：新版专项方法论 → 归档旧稿 → 研究报告 → 外部公开资料。
- **文档互链**：README、USEME、RULES、相关业务/技术/研究目录、memory-bank 索引、Skills 说明等。
- **合规提示**：涉及客户/合作方时使用匿名或公开信息，避免敏感数据；如需对外引用，附上合规确认记录。

## 5. 质量指标
| 维度 | 指标 | 目标值 | 验证方式 |
| --- | --- | --- | --- |
| 完整性 | 七大域覆盖率 | 100% | README 目录 + `find` 检查文件存在 |
| 准确性 | 指标口径一致性 | ≥95% | 对比业务/财务最新指标 |
| 复用率 | 简介被引用的 /spec、方案数量 | ≥60% | Summary 统计 |
| 更新频率 | 每半年复核 | 100% | `last_update` 字段 + changelog |
| 互链完整性 | 每份简介互链 ≥5 条 | 100% | 自检 Checklist |

## 6. 交付清单与模板
- **Checklist**（可复制到 /spec）：
  1. [ ] 明确垂直域价值主张与边界
  2. [ ] 收集核心指标（来源、口径、更新时间）
  3. [ ] 精炼 2-3 个典型场景，补充案例或外部引用
  4. [ ] 列出现有方法论、工具、 Skills 的引用路径
  5. [ ] 自检 Frontmatter、引用格式、互链
  6. [ ] Summary 记录对齐结论与验证方式

- **提示词片段**（Collect 阶段）：
  > “请总结 `💰 投资决策方法论/专项方法论/` 中可用于垂直专业简介的核心指标与案例，并标注来源路径。”

- **验证模板**：
  ```markdown
  ## 验证记录
  - [2025-11-02] 与业务负责人对齐核心指标（会议纪要链接）
  - [2025-11-02] 指标核对：收入同比 +40%（数据来源：财报 Q3）
  - [2025-11-02] Summary 已记录互链更新（README、memory-bank）
  ```

## 7. 维护责任
- **所有者**：每个垂直域指定 1 名内容负责人 + 1 名审阅人（见 README “方法论域分类”章节）。
- **更新节奏**：常规每半年审阅一次；若业务策略重大调整（>10% 指标变动、产品线调整）立即更新。
- **审阅流程**：提交 PR → 领域负责人审阅 → Memory Curator 复核互链 → 合并发布。
