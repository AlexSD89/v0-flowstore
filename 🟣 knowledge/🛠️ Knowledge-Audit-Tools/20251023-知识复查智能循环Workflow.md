# 知识复查智能循环 · Workflow

## 1. 任务定位
- **目标**：校准知识域内所有历史观点、数据、趋势；识别“可信信号”并扩张；形成持续的 BMAD/Rube/MCP 自动化循环。
- **角色**：Claude Code (CC) 作为执行智体，需按本文工作流调用知识库文档与自动化脚本。
- **成果**：每篇文档补齐 `[2025-10 观点复查]` 段、`perspective_registry` 数据更新、可信人物名单扩充、周度汇报。

## 3. Workflow 总览
```
Phase 0  共识与建模 → Phase 1  全量复查 → Phase 2  信号扩张 → Phase 3  监控与汇报
```

### 信号定义速览
- **观点信号（Perspective Signal）**  
  - 由文档中的“陈述 + 预测 + 佐证”构成。复查后若在 2025Q3 得到验证，需在原文 `[2025-10 观点复查]` 中标记 `status: verified`、写明决定性证据，并写入 `perspective_registry` 以便统计命中率、生成图表。  
- **来源/人物信号（Trusted Source Signal）**  
  - 指发出正确观点的个人、团队、平台或节目。将其录入 `trusted_signals`（字段包括领域、历史命中率、常用渠道等），后续 BMAD/Rube 以其为优先抓取对象。  
- **循环目标**  
  1. 逐条验证观点是否正确、为何正确/错误；  
  2. 把正确观点对应的“信号源”纳入可信名单，并在之后持续跟踪、扩充数据。

### Phase 0 · 共识与建模
1. 读取必读资料，确认目录 Owner 与责任分工。  
2. 在 BMAD 中建立 `perspective_registry`、`trusted_signals` 数据集。  
3. 记录当前巡检结果：调用 `knowledge_audit.py` → 生成 baseline。

### Phase 1 · 全量复查
1. **任务派发**  
   - 读取 `复查任务清单` 与目录复查日志，生成待处理队列。
2. **文档处理标准**（针对每篇文档）  
   - 补齐 frontmatter 必填字段。  
   - 新增 `[2025-10 观点复查]`，写入：结论状态、证据、缺口、可信人物、后续动作。  
   - 更新 `last_update`，在 `related` 添加本 Workflow 与复查日志。  
3. **证据收集策略**  
   - 多源验证：Stanford HAI / 政策追踪 / 市场数据。  
   - 时间序列对比：观点预测指标 vs 2025Q3 实际值 → 生成表/图。  
   - 定量评分：准确度、证据强度、复用价值。  
4. **数据写回**  
   - BMAD 更新 `perspective_registry`；  
   - 对可信人物/团队更新 `trusted_signals`；  
   - 在 `09_周报月报/知识复查周志` 记录本轮动作；  
   - 若缺数据，创建 follow-up 任务，挂到复查日志。

### Phase 2 · 信号扩张
1. 维护 `trusted_signals` 数据集（推荐字段：`signal_id`、`signal_type`、`name`、`primary_channel`、`tracking_keywords`、`hit_rate`、`last_verified`、`follow_up_due`）。  
2. 对命中率高的来源，使用 MCP/BMAD 抓取其 **过去 6 个月** 的观点与数据，形成 `signal_snapshot`（含原文、时间、渠道、主题标签）。  
3. 将新观点按 24h 流水线处理：入 `01_Inbox` → 验证 → 迁移入目标目录，并写入 `[YYYY-MM 观点复查]`。  
4. 如果连续两轮命中率降低，触发“降权/移除”流程；反之则提高抓取频次。  
5. 成功案例与策略沉淀到 `05_方法论中心`（例如《正确信号识别与扩张方法论》）。

### Phase 3 · 监控与汇报
1. 定期巡检：每周运行 `🟣 knowledge/🛠️ Knowledge-Audit-Tools/knowledge_audit.py` + BMAD Dashboard，更新复查任务状态。  
2. 汇报：在 `09_周报月报/2025-XX-知识复查周志.md` 输出“复查进度 + 新信号 + 待补数据”，确保跨团队同步。  
3. 重大结论或风险及时更新 `README.md` 与 `蓝图`，保持信息一致。

## 4. 工具与集成

### 4.1 工具与接口清单
- **BMAD Agents**
  - `bm_perspective_validator`: 解析文档 → 抽取观点 → 调用外部数据 → 生成复查报告
  - `bm_trusted_signal_tracker`: 汇总命中率 → 更新 `trusted_signals`
  - `bm_dashboard_builder`: 汇总完成率、命中率可视化
  - `bm_registry_writer`: 将 perspective/signal 数据写入 JSONL & Markdown
- **MCP / Rube Endpoints**
  - `mcp_stanford_hai`: Stanford HAI 官方数据与报告
  - `mcp_policy_watch`: AI 政策/监管动态（欧盟 AI Act、FDA、SAMR 等）
  - `mcp_market_insights`: 融资/市场数据（CB Insights、Crunchbase 等）
  - `mcp_quickchart`: 预测 vs 实际图表生成
- **现有脚本**
  - `🛠️ 系统管理/.../knowledge/tools/knowledge_audit.py`: frontmatter 与缺口巡检
  - 待补：frontmatter 批量补全脚本、Notion/看板同步脚本

- **BMAD Agents**  
  - `perspective_validator`：抽取观点、调用外部数据比对。  
  - `trusted_signal_tracker`：维护可信源名单。  
  - `dashboard_builder`：生成复查进度可视化。  
- **Rube / MCP**  
  - 数据源：Stanford HAI、政策 API、融资数据库、新闻/市场情报。  
  - 图表：Quickchart / chart-server 构建预测 vs 实际图。  
- **脚本**  
  - `knowledge_audit.py`：质量巡检（frontmatter、缺字段、重复）。  
  - 后续可扩展 frontmatter 批量补全、Notion/看板同步脚本。

## 5. 完成标准（per 文档）
1. frontmatter + `last_update` = 2025-10-XX。  
2. `[2025-10 观点复查]` 段落完整（状态、证据、可信源、后续动作）。  
3. `perspective_registry` 与 `trusted_signals` 数据同步更新。  
4. 像例信号源已记录 `signal_snapshot`（含过去 6 个月观点及其验证状态）。  
5. 若需补数据/访谈，已创建 follow-up 任务并记录路径。  
6. 复查日志中对应条目标记为“已复查”。  
7. 若观点修正/扩展，方法论或蓝图已同步。

## 6. 路径示例
1. `🟣 knowledge/02_分析与洞察/第2轮变化建议_基于AI Agent工程实现的技术架构优化.md`  
   - 检查 2025Q3 SLA、成本 → 写入复查段落 → 更新 registry。  
2. `🟣 knowledge/07_市场项目档案/企业服务/Gate-OS/...`  
   - 核实最新融资/用户指标 → 更新观点状态 → 记录可信信号。  
3. `🟣 knowledge/03_研究报告/...`  
   - 对长报告分段复查，必要时拆分成多个 perspective 项。
