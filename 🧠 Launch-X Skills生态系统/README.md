> **愿景**：将知识域的复盘、案例与方法论转化为可复用的Claude Code Skills，使"知识 → 技能 → 工作流"形成闭环。

## 🧭 技能生态系统架构

### 技能分类体系
基于"知识 → 技能 → 工作流"的转化逻辑，技能分为三大类：

#### 📊 知识转化型技能
- **作用**：将特定知识域的专业内容转化为可复用的技能
- **代表技能**：企业研究分析师、市场情报专家、知识管理大师、深度学习专家
- **知识来源**：🟣 knowledge域的复盘、案例与方法论
- **输出**：标准化技能包，支持工作流集成

#### 🛠️ 工程协作型技能
- **作用**：将技术方案和工程实践转化为可执行的工作流
- **代表技能**：项目架构规划师、技术设计专家、Git协作专家
- **知识来源**：技术最佳实践、工程经验、部署策略
- **输出**：工程化技能包，支持Dev Docs协作

#### 🧠 认知增强型技能
- **作用**：将思维方法和决策框架转化为智能辅助能力
- **代表技能**：认知策略大师、商业决策支持专家、质量验证专家
- **知识来源**：方法论中心、决策框架、思维模型
- **输出**：认知增强技能，支持5步认知法执行

### 技能位置管理
- **根目录技能**：`.claude/skills/` - Claude Code核心技能
- **生态管理**：`🧠 Launch-X Skills生态系统/` - 技能生态系统文档
- **垂直技能**：`🧠 Launch-X Skills生态系统/垂直skills/` - 领域专项技能
- **系统级技能**：`🧠 Launch-X Skills生态系统/0️⃣ 系统级方法论/` - 系统级方法论技能

## 🔄 "知识 → 技能 → 工作流"转化示例

### 1. 知识域到技能转化（市场分析）
```
知识输入：
- 🟣 knowledge域的市场趋势分析报告
- 历史案例和复盘总结
- 分析方法论和最佳实践

技能转化：
1. 市场情报专家技能 → 将知识资产标准化
   - Collect: 整理市场分析框架和数据源
   - Model: 构建趋势识别模型
   - Compare: 对比不同分析方法
   - Align: 确定技能输出标准
   - Deliver: 输出标准化技能包

工作流输出：
- Dev Docs plan.md: 市场分析目标和方法论
- Dev Docs context.md: 当前市场状态和数据源
- Dev Docs tasks.md: 分析执行步骤和质量检查点
```

### 2. 技能到工作流集成（项目交付）
```
技能组合：
1. 项目架构规划师技能 → 项目规划能力
2. 技术设计专家技能 → 技术方案设计
3. Git协作专家技能 → 版本控制协作

工作流集成：
1. 技能组合激活 → 自动化工作流启动
   - 创建 dev-docs/<project>/ 目录结构
   - 初始化标准Dev Docs模板
2. Dev Docs驱动执行：
   - plan.md: 项目目标和技术路线（来自技能组合）
   - context.md: 环境配置和依赖关系
   - tasks.md: 任务分解和执行计划
3. Hooks质量保障 → 监控工作流执行质量
4. 技能反馈优化 → 基于执行结果优化技能
```

### 3. 认知增强的工作流循环
```
认知增强：
1. 认知策略大师 → 5步认知思维指导
   - 为工作流提供思维框架
   - 优化决策过程
   - 增强推理能力

工作流执行：
2. 技能组合 → Dev Docs协作系统
   - 标准化技能执行
   - 外部记忆管理
   - 质量自动保障

反馈优化：
3. 执行结果 → 技能优化
   - 工作流数据反馈到技能
   - 技能性能持续改进
   - 新知识沉淀到知识域
```

## 📝 混合协作技能开发要求

### 技能目录结构（Dev Docs集成版）
每个技能必须包含以下标准结构：
```
skill-name/
├── README.md              # 混合协作说明与角色定位
├── instructions.md         # 5步认知提示模板
├── dev-docs/              # Dev Docs模板目录
│   ├── plan-template.md   # 目标记忆模板
│   ├── context-template.md # 状态记忆模板
│   └── tasks-template.md  # 进度记忆模板
├── scripts/               # 执行脚本
│   ├── cognitive-flow.js  # 5步认知执行脚本
│   └── dev-docs-sync.js   # Dev Docs同步脚本
└── tests/                  # 验证计划
    ├── cognitive-test.md  # 认知流程测试
    └── dev-docs-test.md   # Dev Docs集成测试
```

### Dev Docs映射要求
- **认知到执行映射**：每个技能必须明确5步认知法到Dev Docs三文件的映射关系
- **模板标准化**：使用统一的Dev Docs模板，确保技能间协作一致性
- **实时同步机制**：认知阶段结果必须实时同步到对应的Dev Docs文件
- **质量检查点**：通过Hooks自动监控认知到执行的完整映射

### 混合协作验证标准
- **认知完整性验证**：确保5步认知思维的完整性和可追溯性
- **Dev Docs一致性检查**：验证Dev Docs三文件的内容完整性和一致性
- **映射准确性测试**：测试认知结果到Dev Docs的映射准确性
- **协作流程验证**：验证技能间通过Dev Docs的协作流程

### 写作与维护要求
- **信息来源**：主张本地事实优先（技能脚本、执行日志、Dev Docs记录）；外部仅限官方标准作对照补充
- **输出颗粒度**：
  - `README.md` —— 混合协作说明、角色定位、Dev Docs映射关系
  - `instructions/` —— 5步认知提示模板，需附Dev Docs映射示例
  - `dev-docs/` —— 标准Dev Docs模板，支持认知结果固化
  - `scripts/` —— 认知执行与Dev Docs同步脚本
  - `tests/` —— 认知流程与Dev Docs集成验证手册
- **互链要求**：技能更新后，需在相关方法论、工具、bmad文档中记录引用关系；Summary标注"Skills 生态已更新"
- **巡检节奏**：每月对技能可用性、Dev Docs集成度、认知完整性进行复查，结果回写memory-bank

## ✅ 维护清单

### 技能开发流程
```
[ ] 知识资产收集 → 从🟣 knowledge域收集复盘、案例、方法论
[ ] 技能标准化 → 将知识转化为可复用的技能包
[ ] 工作流集成 → 设计技能到Dev Docs的映射关系
[ ] 质量验证 → 验证技能输出和工作流执行效果
[ ] 生态更新 → 更新技能生态系统索引和互链
```

### 质量保障要求
- **知识来源验证**：确保每个技能都有明确的知识域来源
- **技能标准化**：遵循统一的技能开发标准和模板
- **工作流兼容性**：确保技能与Dev Docs系统完全兼容
- **持续优化机制**：建立技能性能监控和优化机制

> Skills 生态是 LaunchX"知识 → 技能 → 工作流"转化的核心引擎。通过系统化的技能管理，确保知识资产能够高效转化为可执行的工作流，持续支撑 LaunchX 的跨域协作能力。
