# Template-Generator 使用说明（面向 Claude）

本文件说明 **Claude 在什么情况下、如何调用本技能** 来生成模板。

## 1. 触发条件

在以下情况优先考虑使用本技能：

- 用户明确提到“模板/模版/骨架/结构”而非直接要最终内容；
- 用户要启动一个新项目、新技能或新文档类别，希望从规范模板开始；
- 用户抱怨现有文档/技能结构混乱，希望“重做一个结构清晰的版本”；
- 需要为自动化脚本/MCP/bmad workflow 提供可填充的配置或报告模板。

若用户只要求一次性输出（例如“帮我写一篇文章”），不必调用本技能，可直接生成内容。

## 2. 使用步骤

1. **识别模板类型**  
   - 根据用户描述判断属于：技能模板 / 文档模板 / 项目模板 / 配置模板。  
   - 如不确定，主动以简短问题澄清（例如：“这个模板主要是给谁看的？”）。

2. **确认目标目录和参考资产**  
   - 若与 Dev Docs 相关：参考 `🧰 tools/launchx-spec-kit-cli/dev-docs/*.md`。  
   - 若与 Skills 相关：参考 `Skill-Template-Generator` 输出骨架。  
   - 若用户提到具体项目/文档，记录路径用于互链。

3. **选择合适的模板结构**  
   - 技能模板：包含 README / instructions / SKILL.md 三件套的结构说明。  
   - 文档模板：包含元信息区 + 结构化章节。  
   - 项目模板：包含 plan/context/tasks 三文件结构。  
   - 配置模板：包含清晰字段和注释说明。

4. **生成模板草稿**  
   - 使用清晰的标题和小节组织结构。  
   - 对不确定内容使用 `TODO｜待补充：<说明>` 标记。  
   - 避免填入虚构数据或具体结论；重点是“框架”和“字段”。

5. **输出格式**  
   - 仅输出模板本身（Markdown/配置文件等），不加额外解释性文字。  
   - 如需说明使用方式，在模板底部用简短注释说明即可。

## 3. 与其他技能的协同

- 当需要为新技能生成模板时：
  - 建议首先调用 `Skill-Template-Generator` 决定 Skill 类型与 SKILL.md 结构；
  - 然后使用本技能补充 README/instructions 和项目级 Dev Docs 模板。
- 当模板与自动化有关（如 bmad/MCP Workflow）：
  - 在模板中预留配置字段和命令占位符，但不要伪造具体路径或密钥；
  - 提醒用户在 Dev Docs 中记录实际命令与日志路径。

## 4. 质量要求

- 模板必须：
  - 结构清晰、层级分明；
  - 与 LaunchX 现有规范和示例保持一致；
  - 使用中文说明关键字段含义（英文字段名可保留）。
- 若信息不足以明确结构，应在模板中写明限制和所需补充信息，而不是凭空假设。
