# 技术开发｜系统架构与交付蓝图

> **核心命题**：以 BMAD 为底座，将系统架构设计、交付闭环与 AI 协作流程整合为一套可落地的执行蓝图。

## 1. 架构全景

### 1.1 四层架构
| 层级 | 关键要素 | 设计要点 |
| --- | --- | --- |
| **体验层** | Web / Mobile / Agent Console | 统一 Next.js + React 架构，采用分层路由与 Suspense，支持 A/B 实验。 |
| **协作层** | BMAD Agent Mesh、工作流编排、事件总线 | 通过 Saga + EventBridge 实现跨 Agent 状态同步，缓存使用 Redis Cluster。 |
| **能力层** | AI 模型、规则引擎、知识库、工具链 | 模型服务走 Triton + OpenAI 混合部署，规则引擎采用 JSON-LD 协议。 |
| **数据层** | Lakehouse、指标仓、审计日志 | Iceberg + DuckDB 双轨方案，指标仓与监控共用统一度量命名。 |

### 1.2 技术选型基线
- 编程语言：TypeScript / Python 双引擎。
- API Gateway：BFF + GraphQL Federation，关键接口预置 3 种限流策略。
- Observability：OpenTelemetry + Prometheus + Grafana，指标命名遵循 `bmad.<service>.<metric>`。

> 详情参考 archive 中《系统架构设计方法论》段落；当前版本保留核心决策，移除过时依赖（如 Next.js 13）。

## 2. 组件与接口规范

### 2.1 组件库策略
- 组件分层：Foundation（原子组件）、Composite（业务复合组件）、Experience（场景组件）。
- 设计标准：遵循 LaunchX 设计系统 token（颜色/间距/字体），Storybook + Chromatic 作为验证工具。
- 发布流程：feature → preview → release 三阶段，采用 Changeset 自动生成版本号。

### 2.2 API 契约
- **写接口**：一律要求 `idempotency-key`，失败需返回语义化错误码。
- **读接口**：支持 cursor-based pagination，默认字段集与扩展字段分离。
- **事件接口**：所有跨服务事件具备 schema registry 校验，配合 DLQ（死信队列）兜底。

### 2.3 安全与合规
- Zero Trust 原则：所有服务间通信要求 mTLS，密钥托管在 Vault。
- 数据分级：依据《知识管理_知识治理与规则体系方法论》（见下一节）标注数据敏感度，触发不同的留痕与审批。

## 3. 交付闭环（M6 框架升级版）

### 3.1 三维价值评估 Matrix
| 维度 | 指标 | 目标 | 依据 |
| --- | --- | --- | --- |
| Business | ARR 提升、客户留存率 | ARR ≥ +25%，留存 ≥ 85% | 复用 Collect 阶段商业假设，按周复盘 |
| Machine | 模型命中率、推理成本 | 命中 ≥ 92%，成本 ≤ 0.18 USD/1K tokens | Observability 仪表板实时拉取 |
| Action | SOP 执行合规率、自动化覆盖率 | 合规 ≥ 95%，自动化 ≥ 70% | Workflow 日志与 QA 样本 |

### 3.2 交付节奏
1. **Sprint-0**：搭建数据接入、灰度环境、基线指标。
2. **Sprint-1/2**：关键用例上线并绑定指标；失败用例进入对齐工单。
3. **Sprint-3+**：规模化扩展 + 技术债清理，Archive 阶段沉淀评估脚本。

### 3.3 QA 与回归
- L0 Check：Lint / TypeCheck / 单测（Jest + Pytest）。
- L1 Check：Prompt 套件评测覆盖 80% 主流程。
- L2 Check：生产影子流量验证 + 人工抽检 5%。

## 4. 人机协作作战图

### 4.1 Collect → Align → Deliver 映射
- Collect：方案架构师 + Tech Lead 建立 `/spec`，AI Agent（Claude Code）提炼历史案例、设计比较。
- Align：Domain Owner 审核 Compare 结果，冻结方案、风险、fallback。
- Deliver：Codex 执行 `/plan`，BMAD 自动记录执行日志，Memory Curator 负责 Archive。

### 4.2 AI 助手角色
| 助手 | 职责 | 工具 |
| --- | --- | --- |
| Claude Code | 生成架构草图、评审代码片段 | MCP context7、GitHub Copilot（审核模式） |
| Codex CLI | 执行命令、集成测试、文档更新 | Shell + apply_patch + 验证脚本 |
| BMAD Agent | 监控、警报、回滚 | bmad monitor、auto rollback scripts |

### 4.3 工作协议
- 行为守则：所有 AI 产出需人工复核；关键变更提交 `/spec`。
- 信息透明：日志与测试结果统一写入 `/logs/<date>`。
- 回滚策略：保留最近 2 个稳定版本，预置 feature flag 与数据层快照。

## 5. 项目治理

### 5.1 角色分工
| 角色 | 关键职责 | 交付物 |
| --- | --- | --- |
| Technical Director | 定义目标架构、审批风险 | 架构蓝图、风险清单 |
| Engineering Lead | 负责交付闭环与技术债管理 | `/plan`、测试报告 |
| DevOps & SRE | 环境、部署、监控 | Release Note、报警策略 |
| QA Lead | Prompt 评测、回归计划 | 评测脚本、缺陷清单 |
| Memory Curator | 知识回写、互链维护 | Archive 报告、索引更新 |

### 5.2 风险雷达
- 架构复杂度过高 → 触发 Simplify Review（由技术委员会组织）。
- 模型表现不达标 → 启动模型调优循环（Dataset → Prompt → Eval）。
- 交付节奏失控 → 使用 M6 节奏表重新评估资源配置。
